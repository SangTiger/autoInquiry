# form-filler — 문의폼 자동 작성기

외부 회사 문의폼에 **미리 정해둔 내용을 알맞은 칸에 자동으로 넣는** 도구.
사이트별 매크로를 N개 만드는 대신, `profile.json` 하나 + 키워드 사전 하나로 임의 사이트를 커버한다.

## 왜 매크로가 아니라 이걸 쓰나

요즘 문의폼은 대부분 React/Next.js + Radix(shadcn)다. 드롭다운이 네이티브 `<select>`가 아니라
"버튼 클릭 → 떠오르는 목록에서 클릭" 구조라, **좌표 녹화형 매크로(오토핫키 등)는 해상도·렌더 타이밍이
바뀌면 바로 깨진다.** 이 도구는 좌표가 아니라 셀렉터로 움직이므로 그 문제가 없다.

## 설치

```bash
cd ~/tools/form-filler
npm install
npx playwright install chromium   # 최초 1회
```

## 사용법

```bash
node fill.mjs --url <URL>              # 단일 사이트, dry-run (채우고 멈춤)
node fill.mjs --all                    # targets.json 전체, dry-run
node fill.mjs --url <URL> --submit     # 실제 전송
node fill.mjs --all --submit           # 전체 실제 전송
```

| 옵션 | 뜻 |
|---|---|
| `--headless` | 창 없이 실행 (기본은 창 띄움 — 사람이 눈으로 보는 게 안전장치다) |
| `--json` | 결과를 JSON 으로 출력 (다른 스크립트에 물릴 때) |
| `--force` | `out/log.csv` 에 이미 `sent` 로 남은 URL 도 다시 처리 |

**기본은 dry-run이다.** 칸을 다 채우고 스크린샷만 남기고 멈춘다. 실제 전송은 `--submit`을 명시할 때만.

종료 코드: 전부 정상이면 `0`, 스킵·실패가 하나라도 있으면 `1`.

## 설정 파일 2개

### `profile.json` — 내 정보 (여기만 고치면 전 사이트 반영)

`profile.example.json` 을 `profile.json` 으로 복사해서 자기 정보로 채운다.

```json
{
  "company": "스토어링크",
  "name": "담당자 성함",
  "phone": "010-0000-0000",
  "email": "you@example.com",
  "inquiryTypePriority": ["대행사 협업/문의", "협업", "제휴", "..."],
  "sourcePriority": ["검색", "SEARCH", "기타"],
  "agreeRequired": true,
  "agreeMarketing": false,
  "message": "문의 본문..."
}
```

`inquiryTypePriority` / `sourcePriority` 는 **우선순위 배열**이다. 사이트마다 드롭다운 문구가 다르므로
위에서부터 옵션 텍스트에 부분일치하는 첫 항목을 고른다. 하나도 안 맞으면 **임의로 고르지 않고** 그 사이트를 건너뛴다.

> `profile.json` 과 `out/` 은 `.gitignore` 처리돼 있다 (개인정보·발사 이력).

본문 안의 `{{suffix}}` 자리에 사이트별 문장이 들어간다. 플레이스홀더가 없으면 맨 뒤에 붙는데,
그러면 "감사합니다!" 뒤에 문장이 오는 어색한 결과가 되므로 **플레이스홀더를 쓰는 걸 권한다.**

### `targets.json` — 대상 목록

```json
{
  "targets": [
    {
      "url": "https://example.co.kr/inquiry",
      "formIndex": 1,
      "overrides": { "company": "#corp_name", "message": "textarea[name=q]" },
      "messageSuffix": "특히 귀사 OO 브랜드의 일본 진출 관련해 제안드릴 내용이 있습니다."
    }
  ]
}
```

- `overrides` — 자동 매핑이 못 잡은 칸만 셀렉터로 직접 지정 (`#id` / `[name=x]` / 임의 CSS)
- `answers` — 프로필에 없는 **사이트 고유 필수 질문**에 답 지정. `{ "라벨 일부": "답변" }` (예: `{"캠페인 희망 날짜": "미정 — 협의 후 결정"}`)
- `checkConsents` — 체크할 동의 항목의 라벨 일부. **동의는 사람이 결정한다** — 도구는 확실히 필수인 것만 자동 체크하고, 애매하면 손대지 않는다 (리스페이스의 필수 동의는 라벨이 "네, 동의합니다." 뿐이라 자동 판별 불가)
- `formIndex` — 한 페이지에 폼이 여러 개일 때 쓸 폼을 직접 지정. 로그의 `폼 후보 N개 중 #M 선택` 경고에서 번호를 확인한다. 보통은 자동 선택이 맞으므로 생략
- `messageSuffix` — 본문 `{{suffix}}` 자리에 넣을 사이트별 문장. **동일 문구 대량 발송은 스팸 처리돼서 회신율이 떨어진다.** 사이트당 1~2문장은 바꿔라.

## 자동 매핑이 어떻게 동작하나

### 0단계 — 프레임 선택

폼을 외부 SaaS iframe 으로 심는 사이트가 있다 (리스페이스 → ReCatch). 메인 프레임과 모든 자식 iframe 을
각각 조사해서 **미해결 0 인 곳 우선, 그다음 매핑된 필드가 많은 곳**을 고른다.

### 1단계 — 폼 그룹 선택

한 페이지에 문의폼·상담신청·뉴스레터·사이트검색이 뒤섞여 있는 사이트가 흔하다(세토웍스는 후보 4개).
전부 한 폼으로 보면 "이메일 칸이 3개" 가 되어 매핑이 불가능하므로, 먼저 필드를 그룹으로 나눈다.

- `<form>` 요소 단위, `<form>` 밖 필드는 **자기 제출 버튼까지 품는 최근접 블록** 단위
  (단순히 "필드 N개를 품는 조상" 으로 하면 그리드 레이아웃의 행 단위로 쪼개진다)
- 각 그룹을 점수화 — textarea 있음(+6) · 이메일(+3) · 연락처(+2) · 회사(+2) · 제출버튼(+1), 단일 필드나 검색 폼은 감점
- 최고점 그룹 1개만 채운다. **동점이면 채우지 않고** `formIndex` 지정을 요구한다

### 2단계 — 그룹 안에서 필드 매핑

`name` · `id` · `label` · `placeholder` · 주변 텍스트 5개 신호에 키워드 사전을 걸고 점수를 낸다.
타입 힌트(`input[type=email]`, `textarea`)가 가장 강한 신호다.
`<label>` 로 묶이지 않은 커스텀 폼은 **필드 앞의 가장 가까운 텍스트를 라벨로 추정**한다.

| 프로필 키 | 잡는 키워드 (일부) |
|---|---|
| `company` | 회사·업체·기업·법인·상호·제품명·company·corporate |
| `name` | 성함·이름·담당자·name·customer (회사 신호가 있으면 탈락 — 회사명 칸 오탐 방지) |
| `phone` | 연락처·전화·휴대·mobile·phone·tel1~3 |
| `email` | 이메일·메일·email |
| `message` | 문의·내용·메시지·본문·message·inquiry·content |
| 드롭다운 | `유형·종류·카테고리·type` → 문의유형 / `경로·알게·유입·source` → 유입경로 |
| 체크박스 | `[선택]·마케팅·수신` → 선택동의 / `[필수]·개인정보·약관` → 필수동의 / 그 외 → **손대지 않음** |

**연락처 분할** — `010 / 1234 / 5678` 처럼 칸을 쪼개 받는 폼을 지원한다(세토웍스가 3칸).
칸 수와 번호 조각 수가 안 맞으면 채우지 않고 미해결로 올린다.

**동의 처리 원칙** — 동의는 사람의 결정이다. `targets.json` 의 `checkConsents` → `[필수]`·`required` 표기 →
`개인정보`·`약관` 문구 순으로만 자동 체크하고, **그 외는 건드리지 않고 경고**한다.
"동의" 라는 단어만으로 체크하면 트래킹 동의까지 눌러버린다(리스페이스 "'고객 여정 데이터 수집' 동의").
신호는 라벨 → 주변 텍스트 순으로만 본다 — 넓은 문맥까지 보면 나란히 붙은 옆 항목 문구가 섞여 오분류된다
(퍼그샵은 필수/선택 동의가 붙어 있어 한 덩어리로 읽힌다). `[필수]` 표기는 마케팅 키워드보다 우선한다
(세토웍스 "[필수]마케팅 활용에 동의합니다").

새 사이트에서 못 잡는 작명이 나오면 `lib/map.mjs` 의 `KEYWORDS` 에 단어를 추가하거나,
그 사이트만 `targets.json` 의 `overrides` 로 처리한다.

## 안전장치 (일부러 넣은 제약)

| 장치 | 이유 |
|---|---|
| dry-run 기본 · `--submit` 명시 필수 | 오타사를 상대 회사에 보내는 건 되돌릴 수 없다 |
| **필수칸 매핑 미해결 시 그 사이트 전체 스킵** | 엉뚱한 칸에 개인정보 넣고 전송하는 사고 방지 |
| 동점 후보가 있으면 채우지 않고 `ambiguous` 보고 | 임의 선택 금지 |
| 입력 후 페이지에서 값을 **다시 읽어 검증** | "채우는 코드가 돌았다" ≠ "칸에 값이 들어갔다" |
| **화면 밖(x<0) 숨은 사본 폼 제외** | 아임웹류는 위젯 원본 폼을 캔버스 밖에 숨겨둔다. 이걸 채우면 **화면엔 아무것도 안 들어갔는데 검증은 통과하는** 최악의 상황이 된다 (세토웍스에서 실제로 겪음) |
| 캡차 감지 시 자동 우회 안 함 | 사람에게 넘긴다 |
| `log.csv` 기준 중복 전송 차단 | 같은 회사에 두 번 보내는 사고 방지 |
| 사이트 간 3~7초 지연 · 동시성 1 | 상대 서버에 부하 주지 않는다 |

### 실제로 부딪힌 함정들

| 함정 | 대응 |
|---|---|
| Radix 숨은 `select[aria-hidden]` 에 값 직접 대입 → React state 미동기화로 **제출 시 빈 값** | 트리거 클릭 → 옵션 클릭 경로로만 선택 |
| Radix 미러용 `input[type=checkbox]` 가 중복 필드로 잡혀 **같은 동의를 두 번 토글** | 미러 input 은 필드에서 제외, `button[role=checkbox]` 만 사용 |
| 커스텀 스타일 체크박스: 실제 input 이 `x=-2020 · opacity:0` 에 있어 클릭 타임아웃 | `setChecked` → `label[for]` 클릭 → 감싼 `<label>` 클릭 → force click → DOM native click 5단 폴백. **`el.checked = v` 직접 대입은 쓰지 않는다** — React 상태와 desync 되어 화면은 체크됐는데 제출은 미체크로 간다 |
| 제출 버튼이 `type=submit` 이 아님 (`<input class="regbtn" type="button" onclick>`) | 클릭 가능 요소 타입 전체를 훑되(`button`/`input[button\|submit]`/`a`/`[onclick]`/`[role=button]`) 텍스트 길이 30자 이하로 제한해 라벨 오인 방지 |
| 긴 폼에서 필드가 뷰포트 밖이라 force 클릭도 거부됨 | 액션 전 `scrollIntoViewIfNeeded` |
| 필수 표시 `*` 를 **CSS `::after`** 로 넣어 `innerText` 로 안 잡힘 (ReCatch) | 조상 블록의 `::after`/`::before` content 까지 검사 |
| 사이트가 연락처 하이픈을 떼어 검증이 실패 (`010-1234-5678` → `01012345678`) | 연락처는 숫자만 비교 |
| "동의" 라는 단어만 보고 트래킹 동의까지 체크 | 필수 표기·개인정보/약관 문구만 자동 체크, 나머지는 손대지 않고 경고 |
| 조상의 `*` 가 번져 `[선택]` 항목까지 필수로 과탐 | 필수 경고는 체크박스 **자기 문구**에만 근거해서 낸다 (과탐은 스킵 쪽이라 안전) |

## 산출물

```
out/
├── shots/{host}-{ts}-before.png   # 채운 직후 (dry-run은 여기까지)
├── shots/{host}-{ts}-after.png    # 제출 후 (--submit 일 때만)
└── log.csv                        # ts,url,status,mapped,unresolved,http,shots
```

`status`: `dry`(채움만) · `sent`(전송) · `skipped`(안 건드림) · `failed`(입력/검증/전송 실패)

## 구조

| 파일 | 역할 |
|---|---|
| `fill.mjs` | CLI · 실행 흐름 · 스크린샷 · 로그 · 제출 게이트 |
| `lib/inspect.mjs` | DOM → 필드 인벤토리 (`data-ff-idx` 부착, 폼 그룹 분리, 라벨·필수표시 추론, 캡차·제출버튼 탐지) |
| `lib/map.mjs` | 인벤토리 → 프로필 매핑 (키워드 사전 + 점수 + 미해결 판정) |
| `lib/act.mjs` | 위젯별 입력 액션 + 입력 결과 검증 |

## 검증 이력

전부 **dry-run** 이며 실제 제출은 한 건도 하지 않았다.

| 대상 | 결과 |
|---|---|
| `partners.pugshop.co.kr/contact` (Next.js + Radix) | ✅ 9칸 전부 자동 매핑 (회사명·성함·연락처·이메일·문의유형·유입경로·본문·필수동의·마케팅해제), `unresolved` 0, 스크린샷 육안 확인 |
| `setoworks.com/contact` (아임웹류 · 폼 후보 4개 · 연락처 3분할) | ✅ 10칸 전부 자동 매핑, 올바른 폼(`div#form_div1`) 선택, 제출버튼 탐지, 스크린샷 육안 확인 |
| `respace.co.kr/contact` (ReCatch **iframe** · name/id 없음 · `::after` 필수표시) | ✅ 7칸 전부 (라벨 추론만으로 매핑), 동의는 `checkConsents` 로 명시 지정, 트래킹 동의는 미체크 유지, Ant 체크박스 React 상태(`-checked` 클래스)까지 확인 |
| `partners.pugshop.co.kr/` (폼 없는 페이지) | ✅ negative test — `SKIPPED` + exit 1, 아무 칸도 건드리지 않음 |
| `--all` 배치 (3사이트) | ✅ exit 0, 경고 잡음 없음 |

## 남은 일

- 외부 사이트를 더 넣어 매핑 사전 커버리지 확대 (`--all` dry-run 으로 측정)
- 캡차 있는 사이트의 수동 처리 흐름은 아직 실전 검증 안 됨 (탐지 → 스킵까지만 확인)
- 발사 이력을 `~/saleslink` 리드·Activity 모델과 연결해 **발송 → 회신 → 미팅 전환율** 추적 (별도 작업)
